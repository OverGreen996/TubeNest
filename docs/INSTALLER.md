# 安裝與修復精靈

## 給使用者

1. 下載發行頁頂端的 **TubeNest-Setup-1.0.3.exe**，直接開啟。不用解壓、不用輸入指令。
2. 精靈偵測 Chrome／Edge；只裝一個就預選，有兩個可選擇。首次安裝選「標準安裝」；已安裝者預選「檢查與修復」。
3. 按開始。下載時顯示目前元件百分比、已下載／總容量、平均實際速度；無法取得總容量時只顯示已下載容量，不捏造百分比。驗證與解壓時顯示具體階段。
4. 助手通訊檢查通過後按「開啟 Chrome／Edge 擴充頁」。資料夾路徑會自動複製。
5. 第一次：開啟開發人員模式 → Load unpacked（Chrome：載入未封裝項目；Edge：載入解壓縮，名稱依語言版本不同）→ 貼上路徑 → 選擇資料夾。已安裝者按 TubeNest「重新載入」，再重新整理 YouTube。

安裝至目前帳號 `%LOCALAPPDATA%\TubeNestYouTube`。開始功能表「TubeNest 安裝與修復」可再次開啟；沒有開機啟動、排程、服務、常駐安裝程式或系統匣圖示。

瀏覽器的首次載入需要使用者操作，精靈不直接修改瀏覽器設定檔或安裝政策，也不把「本機助手已安裝」當成「瀏覽器擴充已啟用」。

## 修復範圍

- 比對正式擴充與助手檔案，檢查版本與內容差異。
- 啟動 yt-dlp、FFmpeg、ffprobe、Deno 的版本檢查，找出缺少或不能執行的工具。
- 檢查偵測到的瀏覽器之目前帳號 Native Messaging 註冊、助手路徑、通訊型別與允許的擴充來源。
- 重新部署正式檔案、重建 Chrome／Edge 助手註冊。缺失或損壞工具重新從官方下載並核對 SHA-256；正常工具沿用。
- 可選同時取得工具最新官方發行版本。更新不能保證突破所有來源限制。
- 完成前以真正 length-prefixed Native Messaging 啟動正式助手，發送不建立工作之取消請求，核對回應並確認 EOF 後退出。

結果顯示於「安裝詳細資訊」，紀錄保存在 `setup.log`。不修改影片、瀏覽器開發人員模式、擴充啟用狀態、企業管理政策、登入資料或網站限制。

## 實作與驗證

單一 Windows x64 .NET Framework WinExe，內嵌 WPF 介面與發布 ZIP。解壓檢查路徑、數量和大小，拒絕越界項目；僅在自己建立的 GUID 暫存目錄內清理。隱藏 PowerShell 與子程序由 kill-on-close Job Object 管理。取消後清理本次暫存，保留安裝完成的工具供重試。

`scripts/Build.ps1` 編譯助手、封裝 payload、編譯安裝精靈，產出 EXE、備用 ZIP 及 SHA-256。

`tests/setup.ps1 -Run` 編譯測試控制程式，使用正式介面、正式安裝後端及官方下載測試獨立目錄；暫時註冊測試助手，結束時還原僅限 TubeNest 的兩個註冊值。不要與正式下載工作同時執行。測試控制程式及工具不隨安裝檔發布。

實測證據與限制見 [VALIDATION.md](../VALIDATION.md)。
